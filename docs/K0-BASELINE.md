# K0: baseline and goldens — gate report

Date: 2026-09-24. Host: MacBook Pro (Mac15,6, Apple M3 Pro, 18 GB, macOS).
Upstream kev pinned at `557598fced1dada75dfbf36ed144dce309ac6ceb`.

## What exists

  versions upstream's own `uv.lock` resolves: torch 2.8.0, transformers
  5.17.0, peft 0.21.0, mlx 0.32.2, mlx-lm 0.31.3, tokenizers 0.23.2,

## What was measured

- **Instrumented vs native**: max abs diff 0.0 (bitwise) on every
  checkpoint and path.
- **Determinism**: repeated native passes bitwise-identical on every run.
- **MLX vs fp32** (`mlx-vs-fp32.json`): kev-0.8b max |dp| 0.0141, mean
  0.0026, 1 argmax flip at fp32 top-2 gap 0.004 (a near-tie; upstream
  allows flips below gap 0.02). kev-4b (10 core-subset questions) max |dp|
  0.0071, mean 0.0018, 0 flips. Upstream's own envelope at the pinned
  commit: 4B max 0.0252 / mean 0.0016 / 1 flip in 1264; 0.8B max 0.0542 /
  mean 0.0023 / 4 flips.
- **Packed vs separate**: torch fp32 max |dp| 1.1e-6, 0 flips (row
  isolation exact); mlx max |dp| 0.0047, 0 flips (upstream bounds variant
  agreement at 0.01).
- **Prefix cache vs native**: mlx 0.0 (exact replay); torch fp32 max
  1.2e-6.
- **Benchmarks** (`results/l0-bench`, median of 20, new/repeated state):
  kev-0.8b mlx 163/66 ms; kev-4b mlx 951/373 ms; kev-0.8b fp32 cpu
  5148/3228 ms; kev-0.6b fp32 cpu 492/240 ms. Upstream's M5 numbers
  (149/28, 721/136) are context, not targets; K2 gates against this host's
  Python medians (`benchmarks/manifest.json`, frozen).
- **Escaping**: the escape fixtures leak zero structural special-token ids;
  the count of special ids equals the structural count exactly (tested).

## Frozen gates

- `benchmarks/goldens/tolerances.json`: instrumented 1e-9; prefix 1e-5
  (torch) / 1e-6 (mlx); packed-vs-separate 1e-5 (torch) / 0.01 (mlx);
  mlx-vs-fp32 per checkpoint from upstream's envelope (0.8B: 0.06/0.005/2
  flips; 4B: 0.03/0.004/1 flip; flips only on top-2 gap < 0.02).
- `benchmarks/manifest.json`: workload, protocol, reference medians and
  the K2 acceptance rule (Rust MLX ≤ 1.10× Python MLX median, p95 ≤ +5%;
  CPU correctness-gated only).

## Limits and deviations (documented, not silent)

1. **kev-4b torch-fp32 is a core subset** (8 fixtures: primitives, packed
   vs separate, escaping). The fp32 4B model needs ~16.5 GB; this host has
   18 GB and swapped heavily (first full-set fixture took >45 min). The
   full 22-fixture set needs a ≥32 GB host; the subset reason is recorded
   in that run's `run.json`. The 4B MLX goldens cover all 22 fixtures and
   upstream's 1024-record parity report anchors the MLX↔fp32 envelope.
2. **kev-0.6b has no MLX goldens** — upstream refuses attention-only bases
   on MLX — and no fitted temperature (serves at T=1.0). It is the honest
   CPU-generation fallback for K1.
3. **CPU fp32 timings use reference GDN kernels** (`causal_conv1d` and
   `flash-linear-attention` are not installed); upstream's macOS CPU path
   has the same fallbacks. Recorded in `benchmarks/manifest.json`.
4. **Hard offline mode is not enforced** during golden generation:
   huggingface-hub 1.32 cannot list a repo tree offline and upstream's
   `resolve_run` calls `snapshot_download` itself. All revisions are
   immutable commit hashes and `kev-fetch --verify-only` re-hashes the
   cache, so the pin still holds.

## Handoff to K1

- The MLX backbone risk is Qwen3.5's hybrid layers (Gated DeltaNet +
  gated attention) in mlx-rs; upstream leans on mlx-lm's implementation.
- kev-metal must share laya-rs's patched mlx-sys 0.6.0
  (`23fff422666fd5039998fd8a55ca57f7e40d224b`), the pin systemone already
  carries. Verify one-binary linking early.
- CPU candidates to evaluate: Candle and llama.cpp for the hybrid
  backbone; if Qwen3.5 CPU is not feasible, kev-0.6b (Qwen3,
  attention-only) is the honest first CPU target and its fp32 goldens are
  complete.
